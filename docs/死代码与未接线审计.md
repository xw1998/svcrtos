# SVCrtOS 死代码 / 未接线审计（2026-09-12）

> 本文只记录**可复现命令能验证的事实**，不含"应该没问题了"这类结论。

## 一、为什么要做这次审计

前面两轮已经修掉一批问题，但都是"语法校验通过 + 符号能链接"就认为没事。
实际上有两类缺陷这两个手段都抓不到：

1. **代码写好了、编译通过、符号也存在，但根本没有人调用**（未接线 / 死代码）；
2. **配置宏被板级文件覆盖成 0，整条功能路径不参与编译**，看源码却"什么都有"。

本轮补了两个审计手段：

- 链接级符号审计（`patch/link_audit.py`）：编全部 `.o`，比对"已定义 / 未定义"符号，
  查漏编文件、漏实现、重复强定义。
- 死代码审计（`patch/deadcode_audit.py`）：编全部 `.o`，扫描 `.rel/.rela` 重定位表，
  找出"有全局定义但没有任何引用（含同文件内调用、函数地址被放进结构体/向量表）"的函数。

```bash
python patch/link_audit.py        # 未解析符号 / 重复强定义
python patch/deadcode_audit.py    # 零引用函数清单
```

另外用预处理器核对配置宏的**真实取值**（板级头文件会覆盖）：

```bash
armclang -E -dM ... kernelsrc/src/svcrt_loader.c | grep -E "APP_CRASH_RESTART_MAX|INSTALLER_|SVCRT_USE_"
```

## 三、审计发现但**尚未处理**的问题（需要你决策）

### 3.1 隔离（MPU / 非特权）代码路径已完整，开关仍是关的

> 第五轮更新：区域构建、端口编码、任务切换重放已全部接好（见第七节 7.1）。
> 板级 `SVCRT_USE_MPU` / `SVCRT_USE_PRIV` **仍为 0**，原因不再是"没写"，
> 而是"没有硬件标定"——打开它之前必须先按第 7.4 节的清单在板上量一遍。

```
#define SVCRT_USE_MPU   0     ← 板级 svcrt_board_config.h 覆盖
#define SVCRT_USE_PRIV  0     ← 任务以特权模式运行
#define SVCRT_ARCH_HAS_MPU 1  ← 芯片有能力，但被关掉了
```

后果：`svcrt_port_mpu_init()`、`svcrt_port_mpu_set_app()`、`svcrt_mpu_*`、
`svcrt_port_set_idle_mpu()` 全部不参与编译或零调用。
即"应用越权访问别人的内存会被拦住"这件事**目前不成立**。

**已接线（2026-09-12 第二轮）**：

- 修掉 MPU 数据区属性位错误：`ram_asr` 的 AP 域是 `0b011`（非特权**只读**），
  非特权任务写自己的 RAM 会立刻 MemManage → 改为 `0b010`（非特权可读写），m3/m4 各一处；
- 补上缺失的 `kernelsrc/src/svcrt_mpu.c`：原 `svcrt_mpu.h` 声明了 4 个函数却没有任何实现文件，
  一旦被调用就是链接错误。现为薄封装（硬件操作仍在 port 层），内核侧调用统一到该层：
  `svcrt_sched_activate()` → `svcrt_mpu_set_app()`、`svcrt_kernel_module_init()` → `svcrt_mpu_module_init()`；
- `svcrt_mpu.c` 已加入内核工程文件表；删掉没有对接点的 `svcrt_mpu_set()`；
- 验证：用临时板级配置头把 `SVCRT_USE_MPU`/`SVCRT_USE_PRIV` 置 1，
  `svcrt_mpu.c` / `svcrt_task.c` / `svcrt_init.c` / `svcrt_port.c` / `svcrt_board.c` AC6 语法校验全部通过。

**打开隔离前仍缺的最后一步（需你拍板）**：为每个任务填充 TCB 里的 `mpu` 区域上下文。
目前 `svcrt_task_register()` 只把它清零 → 区域全 0 = 全部禁用，非特权任务访问任何地址都会 fault。

1. 任务代码区（只读可执行）+ 任务 RAM/栈区（读写、不可执行）—— 这两条必配；
2. **外设区（0x40000000 起）是否放行**：不放行则 LED/UART 等所有外设访问都会 fault；
   放行则隔离强度下降。当前内核内置任务与 App 都直接操作寄存器，必须二选一；
3. MPU 对特权模式默认放行（`PRIVDEFENA=1`），只有 `SVCRT_USE_PRIV=1`（非特权）时隔离才真正生效；
4. 以上任何选择都必须上板验证，无法只靠静态检查确认。
