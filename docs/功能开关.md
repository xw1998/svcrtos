# SVCrtOS 功能开关

## 一句话

内核里每一块"不是每个系统都要"的功能，都有一个开关；开关的表在
`kernelsrc/include/svcrt_features.h`。关掉以后不是"编不过"，而是那块功能
不存在，并且**它对外说的每一个字都是实话**。

## 怎么用

三种改法，任选一种：

1. 直接改 `svcrt_features.h` 里的默认值（简单，但会出现在 diff 里）
2. 在 `svcrt_config.h` 之前定义，覆盖默认值：
   ```c
   #define SVCRT_USE_FS   0
   #include "svcrt_config.h"
   ```
3. 工程宏（Keil：Options → C/C++ → Define）：
   `-DSVCRT_USE_FS=0 -DSVCRT_USE_MDK_TRACE=0`

`svcrt_features.h` 里每一项都是 `#ifndef / #define / #endif`，所以外部定义
永远优先。

## 开关分三层，不要混

| 层 | 管什么 | 放哪 | 例子 |
|---|---|---|---|
| 能力层 | 这颗芯片**有**什么 | 板级配置 `board/*/svcrt_board_config.h` | `SVCRT_USE_FPU` / `SVCRT_USE_MPU` / `SVCRT_USE_PRIV` |
| 选配层 | 这次构建**要**什么 | `svcrt_features.h` | 本文下面全部 |
| 既有配置 | 早就存在、另有一个名字 | `config/svcrt_partition.h` | `SHELL_ENABLE` / `INSTALLER_ENABLE` |

能力层描述硬件事实，选配层描述软件取舍 —— 一个开关只能属于一层。
Shell 的开关**不在** `svcrt_features.h`：它叫 `SHELL_ENABLE`，在
`config/svcrt_partition.h`，`svcrt_shell.c` 的整文件门控与关闭时的空实现
一直在那儿。不要在 `svcrt_features.h` 里再写一个 shell 开关。

## 开关清单

### 一、内核基础机制

| 开关 | 关掉后 |
|---|---|
| `SVCRT_USE_SPINLOCK` | 自旋锁换成**纯关中断**的降级实现（单核够用，省掉原子 CAS 与 SMP 预留）。锁语义仍在，调用方不用改 |
| `SVCRT_USE_SCHED_LOCK` | **不允许关**（置 0 直接 `#error`）。锁语义没有诚实的降级方式，见下文 |
| `SVCRT_USE_STACK_USAGE` | 不再统计每任务栈峰值；`task` 命令那一列打印 `n/a`，不打印 0 |
| `SVCRT_USE_STACK_CHECK` | 不再做栈尾标志检查 |
| `SVCRT_USE_SCHED_STAT` | 调度统计归零（上下文切换次数等） |
| `SVCRT_USE_CPU_LOAD` | 不再可查询 CPU 占用 |
| `SVCRT_USE_FAST_TICK_SWITCH` | 关掉"按需拉 PendSV"的快速路径，回到每个节拍都判定 |
| `SVCRT_USE_FAULT_RECOVER` | 故障发生后不再尝试恢复调度 |

### 二、同步与 IPC

| 开关 | 关掉后 |
|---|---|
| `SVCRT_USE_MQ` | 消息队列服务不存在：创建失败、收发一律拒绝（不会给一个"静默丢消息"的句柄） |
| `SVCRT_USE_TIMER` | 软件定时器不存在：创建/启动一律拒绝，回调永远不会被"答应" |

### 三、服务与组件

| 开关 | 关掉后 |
|---|---|
| `SVCRT_USE_LOG` | 内核日志与控制台一起消失。用户态往控制台句柄写会**走普通设备路径**（`svcrt_console_is_handle()` 返回 0），不是写进黑洞 |
| `SVCRT_USE_BLK` | 块设备层空表，任何读写返回 -1。**依赖：`SVCRT_USE_FS` 必须同时为 0** |
| `SVCRT_USE_FS` | 文件系统门面一律"什么都没挂载"，错误码与真实情况一致 |
| `SVCRT_USE_POSIX` | App 不能再用 `<pthread.h>` 那一套，只能用原生 oslib |
| `SVCRT_POSIX_WRAP_STDLIB` | POSIX 层不再把 `malloc/free` 接到自己的堆（默认就是关的） |
| `SVCRT_USE_MDK_TRACE` | trace 采集整体消失，14 个入口变成空实现 |

### 四、可靠性运维

| 开关 | 关掉后 |
|---|---|
| `SVCRT_USE_CRASH_LOG` | 跨复位崩溃账本不存在：不记录、不因故障次数禁用镜像、区域地址为 0 |
| `SVCRT_USE_KERNEL_GUARD` | 心跳契约关掉：记录是空操作，**显式心跳返回 -1 被拒绝**（不让调用方以为"有人在看着"） |
| `SVCRT_USE_AUDIT` | 结构化自检关掉：报告为空、掩码 0，看到的是"无发现"而不是伪造的健康证明 |
| `SVCRT_USE_CM_BACKTRACE` | 异常回溯组件不参与编译 |

## 两条实现规则

**规则一：被内核热路径调用的模块，用「整文件门控 + `#else` 空实现」。**
`tick`、`SVC` 分派、设备写这些地方不该散落 `#if`，否则代码读起来像打了补丁。
现在这些模块的 stub 一律回答"没有"：失败返回 -1，查询返回 0、NULL 或 `n/a`。
绝不返回一个看着像成功的值。

**规则二：必须为 1 的开关，用 `#error` 挡住，不要留给链接器。**
`SVCRT_USE_SCHED_LOCK` 就是这样：内核侧调用点没有关闭分支，置 0 会让 14 个
符号在链接期才炸。`SVCRT_USE_FS=1 && SVCRT_USE_BLK=0` 同理。依赖关系写在
`svcrt_features.h` 末尾，让编译器在最前面就把话说明白。

## 怎么验证"真能关"

```bash
# 全部选配开关置 0（SVCRT_USE_SCHED_LOCK 除外，它必须为 1）
python3 - <<'PY'
import re, io
p = "kernelsrc/include/svcrt_features.h"
t = io.open(p, encoding="utf-8", newline="").read()
out = []
for l in t.split("\n"):
    m = re.match(r"(#define (SVCRT_USE_[A-Z_0-9]+)\s+)\S+\s*$", l)
    if m and m.group(2) != "SVCRT_USE_SCHED_LOCK":
        l = m.group(1) + "0"
    out.append(l)
io.open(p, "w", encoding="utf-8", newline="").write("\n".join(out))
PY

# 编译（注意 -o 落 C:\tmp，退出码 1 只是 warning）
UV4 -r <工程>.uvprojx -o C:\tmp\trim.log -j0
```

判据是 **0 Error(s)**，并且生成 `.axf`。跑完记得把 `svcrt_features.h` 还原。

本次实测（STM32F427 内核工程，全部选配开关关闭，Shell 仍启用）：

| 配置 | Code | RO-data | RW-data | ZI-data |
|---|---|---|---|---|
| 全开（基线） | 92206 | 7154 | 416 | 51524 |
| 全部选配关闭 | 55530 | 4022 | 316 | 36516 |

代码量降到 **60.2%**。这个数字的意义不是"省了多少"，而是证明这些开关
真的把代码拿掉了，而不是写着好看的假开关。

## 新增一个开关的清单

1. 在 `svcrt_features.h` 对应分组里加 `#ifndef / #define / #endif`
2. 在实现文件里加整文件门控，并在 `#else` 写清"关掉以后调用方看到什么"
3. 若它被内核调用，确认关闭后仍有符号可链（stub），或写明"必须为 1"加 `#error`
4. 跑一次"全关"编译，确认 0 Error
5. 跑一次全开编译，确认 Code 与基线一致
